# 实验设计与分析计划

这个 Skill 把“想验证一个假设”变成“别人可以照着执行、审稿人可以照着复核”的设计。设计必须在看结果之前写完；事后补设计等于给结果找理由。

## 一、什么时候用

适用：

- 有一个明确假设，需要决定怎么测。
- 需要样本量/功效、随机化、对照、批次、重复、统计计划。
- 需要判断一个已有设计是否可行、是否过度、是否有偏倚。
- 需要把探索性分析和确证性分析分开。

不适用：

- 还没有可检验假设（先用 `hypothesis-design`）。
- 只是跑一个已有流程、无需设计决策（直接执行，但要记录参数）。
- 需要写论文（用 `scientific-writing`）。

## 二、产出契约

至少写两个文件：

```text
planning/experiment-design-<slug>.md
planning/sap-<slug>.md
```

`experiment-design` 写“为什么这样设计”；`sap` 写“数据到手后怎么分析”。两者都要有版本号和日期。

### 设计文档必须回答

1. **问题与 estimand**：到底估计什么？是组间均值差、风险比、交互效应、剂量反应斜率，还是预测性能？
2. **实验单位**：独立重复是什么？一只动物、一个供体、一个培养皿、一个孔、一个细胞、一个测序 run？把“技术重复”和“生物学重复”分开。
3. **人群/系统**：物种、品系、性别、年龄、组织、细胞系、纳入/排除标准。
4. **分组与对照**：阴性对照、阳性对照、载体/溶剂对照、未处理对照、基线测量。
5. **随机化**：谁随机、怎么随机、随机化单位、分层因素、盲法（分配/实施/测量/分析）。
6. **区组/批次**：批次、日期、操作者、测序 lane、板号；如何与处理因素解耦。
7. **样本量/功效**：效应量来源、α、power、脱落率、多重性、计算方法和假设。
8. **主要/次要终点**：主要终点只能有一个（或一个明确的多重性校正家族）；次要/探索性要标注。
9. **缺失数据**：可能缺失多少、缺失机制假设、处理策略（完整病例/多重插补/敏感性分析）。
10. **停止/排除规则**：什么情况下停实验、什么数据点可以排除、谁来决定。
11. **材料与流程**：试剂批次、仪器、关键参数、时间线、责任人。
12. **风险与备选方案**：最可能失败的点、备选设计、预实验/可行性检查。

### SAP 必须回答

- 分析人群（ITT/PP/安全集）及定义。
- 主要终点的模型/检验、协变量、效应量与置信区间。
- 多重性校正策略（families、方法）。
- 缺失数据处理与敏感性分析。
- 模型假设检查与不满足时的替代方法。
- 亚组/交互分析（预先声明，禁止事后挖）。
- 软件、版本、随机种子、脚本路径。
- 任何偏离 SAP 的记录方式。

### `plan-steps` 块（供 R1 工具核查）

方案定稿后，在 `planning/experiment-design-<slug>.md` 末尾追加一个 fenced YAML 块。它是机器可读的“执行动作清单”，不是给 SAP 重复统计细节：

````markdown
```plan-steps
version: 1
steps:
  - id: S1
    goal: "对 raw fastq 做质控和接头修剪"
    inputs: ["data/raw/*.fastq.gz"]
    outputs: ["results/qc/*.fastq.gz"]
    current_tool: null
    current_approach: "手写 shell 调 fastp"
    constraints: ["human", "paired-end"]
```
````

规则：

- **一个可执行动作一条**；如果一步同时做 QC + 比对 + 定量，拆成三条。
- `current_tool` 用 toollibrary catalog 的 exact id（如 `scanpy`、`bio-workflow`）；没有库内工具就省略或写 `null`，不要写 display name。
- `current_approach` 写当前打算怎么做（手写脚本/人工/已有工具），供“是否有更合适工具”的比较。
- `inputs` / `outputs` / `constraints` 按需写；它们是判断工具是否对口的上下文。
- 同一个 design 文档只维护一个 `plan-steps` 块；改步骤后重写并重新跑核查。

Researcher 随后调用 `toollibrary action="plan-audit" path="planning/experiment-design-<slug>.md"`。核查只返回建议报告，不修改本文件，也不阻断执行。

## 三、工作流

### 1. 先把问题写成 estimand

用一句话：

> 在 <人群/系统> 中，<干预/暴露> 相对于 <对照> 对 <结局> 的 <效应度量> 是多少，考虑 <伴发事件/截尾>？

如果写不出 estimand，说明问题还太模糊，回到 `hypothesis-design`。

### 2. 选择设计类型

| 问题 | 候选设计 | 关键风险 |
| --- | --- | --- |
| 干预是否有效 | RCT、析因、交叉、整群 | 随机化/盲法/依从性 |
| 暴露是否致病 | 队列、病例对照、横断面 | 混杂/反向因果/选择 |
| 诊断准确性 | 横断面 + 参考标准 | 谱偏倚/验证偏倚 |
| 预后 | 队列、生存分析 | 随访/竞争风险 |
| 机制 | 扰动实验、时间序列、剂量反应 | 特异性/脱靶 |
| 组学发现 | 发现集 + 独立验证集 | 过拟合/批次/多重检验 |
| 方法比较 | 基准数据集 + 分层评估 | 数据泄漏/指标选择 |

不要为了“看起来严谨”做自己没能力执行的复杂设计；先保证可执行和可解释。

### 3. 样本量与功效

最低要求：

- 效应量从哪来：预实验、文献、最小临床/生物学重要差异。不能凭空拍。
- α（双侧/单侧）、power（常用 0.8）、预期脱落率。
- 多重性：几个主要比较？校正后 α 是多少？
- 计算工具：statsmodels、pwr、simr、仿真；写清版本和参数。
- 如果效应量不确定，给出敏感性表（不同效应量 → 所需 n）。
- 如果只能做小样本，明确说“这是探索性/试点，不足以确证”，不要用 p 值硬撑。

常见坑：

- 用技术重复当生物学重复（伪重复）。
- 用 post-hoc power 解释不显著结果。
- 只算一组比较，忽略多终点/多组。
- 忽略脱落和样本质量（RNA 质量、测序失败）。

### 4. 随机化、区组与盲法

- 随机化单位必须与分析单位一致；如果按笼子随机但按动物分析，会低估方差。
- 区组要能吸收已知批次，但不要把处理完全嵌套在批次里。
- 盲法至少覆盖测量和分析；如果无法盲，写清偏倚方向和缓解措施。
- 记录随机化种子/序列，保存分配表。

### 5. 预实验与可行性

在正式实验前做：

- 材料/试剂/仪器可用性检查。
- 关键步骤的小规模试跑（不用于主结论）。
- 数据生成/测序/质控的失败率估计。
- 样本量假设的现实性检查。

预实验数据不能直接并进确证性分析，除非 SAP 预先写了。

### 6. 可复现性契约

设计阶段就写清：

- 原始数据只读，分析输出到独立目录。
- 脚本、参数、版本、种子、命令全部记录。
- 中间结果可重建；最终图表由脚本生成，不手工改。
- 数据/代码存放位置和命名约定。
- 谁有权限、如何备份、如何冻结最终版本。

### 7. 设计评审（自检或 Reviewer）

用下面清单过一遍：

- [ ] 主要终点和 estimand 是否唯一、明确？
- [ ] 对照是否真的能区分假设？
- [ ] 随机化/区组是否与实验单位一致？
- [ ] 样本量假设是否写清、是否现实？
- [ ] 多重性是否预先处理？
- [ ] 缺失数据和脱落是否有计划？
- [ ] 是否有批次混杂？能否解耦？
- [ ] 统计分析是否与设计匹配？
- [ ] 负结果是否仍然有解释力？
- [ ] 伦理/数据许可/安全是否覆盖？

## 四、常见失败模式

| 失败 | 后果 | 修正 |
| --- | --- | --- |
| 先做实验再补 SAP | p-hacking、不可信 | 设计阶段冻结 SAP 版本 |
| 伪重复 | 假阳性 | 明确生物学重复/技术重复 |
| 批次=处理 | 效应不可分离 | 随机化/区组/交叉设计 |
| 样本量拍脑袋 | 功效不足或浪费 | 用效应量+仿真/公式，给敏感性 |
| 多终点不校正 | 假阳性 | 预设主要终点+校正家族 |
| 只报显著 | 发表偏倚 | 预先声明全部终点与分析 |
| 忽略脱落 | 选择偏倚 | 预设缺失处理与敏感性分析 |
| 用 p 值代替效应量 | 无法判断实际意义 | 报效应量+CI |

## 五、与团队的分工

- 你把设计文档和 SAP 交给 Researcher 执行；执行中的偏离必须记录并回报。
- 需要文献支持效应量/方法选择 → 找 Searcher。
- 需要 Reviewer 独立审查设计 → 让 PI 派发；本 Skill 的清单可以直接给 Reviewer 用。
- Writer 写 Methods 时只依据设计文档和实际执行记录，不改设计叙事。
