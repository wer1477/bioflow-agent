# 科学写作与规范报告

## 适用场景

把研究结果组织成论文/预印本/报告；写摘要、方法、结果、讨论；选择报告指南；核对引用；准备投稿与回复审稿；判断一段文字是否过度解释。

## 一、写作顺序：先证据，后故事，再句子

1. **主张-证据矩阵**：每条主张对应图/表/统计/文献/数据路径。
2. **故事线**：一句话核心发现；每节要证明什么。
3. **图表**：先做能承担论证的图/表，再写正文。
4. **正文**：按 IMRaD 写，最后写标题/摘要。
5. **核对**：数字、引用、报告指南、声明。

如果先写好句子再找证据，容易产生“漂亮但站不住”的段落。

## 二、IMRaD 的节段契约

- **Introduction**：已知 → 未知 → 为什么重要 → 本研究问题/假设。最后一段明确目标，不写结果。
- **Methods**：可复现；样本、材料、仪器、软件版本、参数、随机化/盲法、统计、伦理、数据/代码。不要解释结果。
- **Results**：按论证顺序；每段问题 → 方法一句 → 结果（数字/图）→ 边界一句。不在结果里讨论文献。
- **Discussion**：主要发现 → 与已有工作比较 → 机制 → 限制 → 意义/下一步。限制要具体。
- **Conclusion**：只写证据支持的结论；不引入新数据/引用。

**Title**：具体、可检索、不夸大；包含对象/系统/主要发现。
**Abstract**：背景 → 空白 → 方法 → 关键结果（带数字）→ 结论；不引用文献，不写正文没有的结论。

## 三、主张与措辞

- 区分：观察、相关、预测、机制、因果、建议。
- 因果措辞只在设计支持时使用；观察性研究写“与…相关/提示/一致”。
- 避免“显著”代替“重要”；报告效应量和 CI。
- 避免“首次/唯一/证明/彻底改变”，除非有检索和证据支持。
- 负结果/无差异也要报告；不要只报阳性。
- 不要用“可能/或许”堆砌模糊；要么给证据，要么明确写不确定性。

## 四、报告指南

按研究类型选择，逐项填写并保留清单：

| 研究类型 | 常用指南 |
| --- | --- |
| 随机对照试验 | CONSORT |
| 观察性研究 | STROBE |
| 系统综述/meta | PRISMA |
| 动物实验 | ARRIVE |
| 病例报告 | CARE |
| 诊断准确性 | STARD |
| 预后/预测模型 | TRIPOD |
| 机器学习/预测模型 | TRIPOD+AI（或领域版本） |
| 组学 | 领域特定指南（MIAME、MINiML 等） |
| 质量改进 | SQUIRE |

指南不是装饰：缺项写“不适用 + 理由”；不要空着。注册号、方案版本、数据/代码可及性要写。

## 五、统计报告

最低集合：

- 样本量（每组、分析集）和排除流程。
- 主要/次要终点，是否预设。
- 效应量 + 95% CI + 精确 p 值（或明确不等式）。
- 检验方法、单/双侧、校正方法。
- 缺失数据比例与处理。
- 模型假设检查/替代方法。
- 亚组/交互是否预设。
- 软件/版本。

不要：

- 只报 p 值，不报效应量。
- 用“p<0.05”代替精确值（除非 venue 要求）。
- 把不显著写成“无差异”。
- 事后挑检验/终点。
- 用 post-hoc power 解释不显著。
- 把技术重复当生物学重复。

## 六、图表

- 每张图一个清晰问题；面板按论证顺序。
- 图注自足：n、统计、误差棒含义、显著性标记、缩写。
- 展示分布/个体点，不只均值柱；避免误导性截断坐标轴。
- 颜色对色盲友好；避免彩虹色/3D/双 y 轴。
- 表格给精确值；图给趋势/分布。
- 图由脚本生成，保留源数据和脚本路径；不要手工修图。

## 七、引用完整性

- 每条引用核对 DOI/PMID、作者、年份、期刊。
- 引用必须支持对应主张；标题相关不等于支持。
- 优先原始研究；综述用于背景。
- 检查撤稿/更正/表达关注。
- 二手转引回溯原始文献；回不到就标注。
- 统一格式；不要引用读不到的文献凑数。
- 生成式工具不能替代引用核验；所有引用人工/工具核对。

## 八、作者、贡献与声明

- **作者资格**：按 ICMJE 四条标准（实质贡献、起草/修订、最终批准、同意负责）。
- **贡献**：CRediT 分类（概念、方法、软件、验证、形式分析、调查、资源、数据管理、写作、可视、监督、项目管理、资助）。
- **利益冲突**：财务/非财务；即使“无”也要声明。
- **资助**：编号、资助方角色。
- **伦理**：批准号、知情同意、动物福利。
- **数据/代码可及性**：仓库、accession、许可、受限数据申请方式。
- **AI 使用**：按 venue 政策披露工具、用途、人工核验；AI 不能当作者。
- **原创性**：未一稿多投、未重复发表、引用前作、遵守文本重用政策。

## 九、投稿与回复

- **Cover letter**：一句话贡献、为什么适合、原创性声明、通讯作者；不复述摘要。
- **Highlights**：3–5 条可验证发现。
- **Response to reviewers**：逐条编号；引用修改位置（页/行/图）；同意就改，不同意给证据和理由；不情绪化、不回避。
- **修改稿**：标出修改、保持版本、更新图/表/补充材料；回复与正文一致。
- **拒稿/转投**：根据意见修改，不隐瞒先前投稿历史（按 venue 政策）。

## 十、常见误用

- 摘要/标题夸大，正文不支持。
- 把相关写成因果；把体外/动物写成人类。
- 只报阳性结果，隐藏阴性/预设终点。
- 图注缺 n/统计/误差棒。
- 引用不支持主张；引用撤稿文献。
- 方法不可复现；软件版本/参数缺失。
- 作者贡献/COI/数据可及性缺失。
- 回复审稿只反驳不修改。
- 用“首次”但没有检索。
- 把预印本当同行评议论文引用。

## 十一、实践建议

1. 先建 claim-evidence 矩阵，再写。
2. 先定图表，再写 Results；先写 Methods/Results，再写 Intro/Discussion。
3. 每段一个论点；每句能追溯到证据或明确标推断。
4. 统计报告按最小集合逐项检查。
5. 选报告指南并逐项填。
6. 引用逐条核验 locator 和支持关系。
7. 投稿前请独立 Reviewer 审一遍。
8. 保留所有版本、图脚本、数据/代码路径。
9. 措辞与证据强度匹配；不确定就写不确定。
10. 把“未完成/未核实”清单交给 PI，不要偷偷补全。
