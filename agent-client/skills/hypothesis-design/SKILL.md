# 假设生成与比较

这个 Skill 把“一个观察/空白”变成一组可被证伪、可被区分、可被执行的假设。它的核心不是写出漂亮句子，而是让每个假设都能回答：如果它为真，世界会怎样不同；如果它为假，什么观察会杀掉它。

## 一、什么时候用

适用：

- 文献综述或初步观察之后，需要提出可检验的机制/解释。
- 用户问“为什么会这样”“还有什么解释”“这个想法新不新”。
- 需要为实验设计提供候选假设和判别性预测。
- 需要比较多个竞争解释，而不是押注第一个想到的。

不适用：

- 已经有一个明确假设，只需要设计实验（用 `experiment-design`）。
- 需要跑数据验证（交给 Researcher）。
- 需要做完整文献综述（先用 `lit-review`）。

## 二、产出契约

写入 `research/hypotheses.md`，结构固定：

```markdown
# 假设与判别

## 观察/问题
## 候选假设（H1..Hn）
### H1 一句话假设
- 机制：
- 支持证据：
- 反对证据：
- 判别性预测：
- 证伪条件：
- 需要的观察/实验：
- 成本与可行性：
- 新颖性：
- 主要风险：
## 判别矩阵
## 排序与推荐
## 未决问题
```

判别矩阵至少包含：

| 观察/实验 | H1 预测 | H2 预测 | H3 预测 | 能否区分 |
| --- | --- | --- | --- | --- |

“能否区分”必须是明确的：能/不能/需要更高精度。不要写“可能可以”。

### 机器可读产物（跑 hypothesis-screen 时必需）

`research/hypotheses.md` 是人读版；Searcher 需要调用 `toollibrary action="hypothesis-screen"` 时，还要写 `research/hypotheses.yaml`。每张卡至少包含 `id / gapIds / claim / predictions / evidenceLinks / alternatives`，并让 `evidence[].id` 被 `evidenceLinks[].eid` 引用：

```yaml
rq: 研究问题
reviewSummary: 综述摘要（可选）
gaps: [G1, G2]
hypotheses:
  - id: H1
    gapIds: [G1]
    claim: 一句话假设
    mechanism: 机制（可选）
    premises:
      - {pid: p1, text: 可判真假的原子前提, type: empirical}
    predictions:
      - {text: 判别性预测, readout: 读出, direction: 方向, falsifier: 证伪观察}
    evidenceLinks:
      - {eid: E1, relation: supports}
    alternatives: [竞争解释]
    dataNeeded: 需要的数据（可选）
    feasibility: {assay: 方法, sample: 样本, time: 周期, costTier: low}
    noveltyArgument: 新颖性论证（只给 LLM/PI，不进 biod 分数）
    expectedImpact: 影响（只给 LLM/PI）
evidence:
  - id: E1
    locator: 图/表/页码
    snippet: 原文短引
    studyDesign: 设计
    effect: 效应
    limitations: 局限
    context: {species: 物种, system: 体系, direction: 方向}
```

`shortlist` / `ranked` 只影响深审顺序；`deferred` 不是删除；`contradicted` premise 要解释、补证据或降级，不能为了让报告变干净而改假设或引文。

## 三、工作流

### 1. 先固定观察，不急着解释

用一段话写清楚：

- 观察到了什么（数据、文献、现象）。
- 观察的单位、条件、重复数、已知混杂。
- 哪些是事实，哪些是二手转述或推断。

如果观察本身不稳定（批次效应、样本量小、只在一个条件成立），先把“观察是否真实”列为 H0 级别的竞争解释。

### 2. 生成至少 3 个竞争解释

不要只写一个“主假设”再补两个稻草人。常见竞争解释类别：

- **生物学机制**：表达、剪接、蛋白稳定性、定位、相互作用、代谢通量、细胞状态。
- **技术/测量**：批次、归一化、抗体特异性、测序深度、分割误差、阈值选择。
- **统计/设计**：样本量不足、选择偏倚、混杂、回归到均值、多重比较、过拟合。
- **因果方向**：A→B、B→A、共同原因 C→A/B、选择效应。
- **人群/系统差异**：物种、细胞系、剂量、时间窗、组织、遗传背景。

每个假设都要有一句话机制，不能只是“X 与 Y 相关”。

### 3. 写出判别性预测

对每个假设问：

- 如果 H 为真，在**新数据/新条件**下应该看到什么？
- 这个预测和竞争假设的预测有什么不同？
- 需要什么精度/样本量才能区分？
- 如果预测失败，H 是否一定为假，还是只是需要附加条件？

好的预测是具体的、方向明确的、可观测的：

- 好：“H1 预测在敲低 X 后 Y 的蛋白半衰期缩短，而 mRNA 不变。”
- 差：“H1 预测 Y 会变化。”

### 4. 写证伪条件

每个假设至少一条：

- 观察到什么结果就放弃/降权这个假设。
- 哪些结果是“不支持但不致命”。
- 哪些结果会需要引入新假设。

如果写不出证伪条件，这个假设不可检验，改写或删掉。

### 5. 做新颖性检查

用 `lit-review` 的检索流程做一次 bounded novelty check：

- 这个假设是否已被直接检验？结论是什么？
- 是否只是换物种/换组织/换方法重复？
- 增量是：新问题、新机制、新数据、新方法、还是新应用？
- 最接近的 3–5 篇工作是什么？它们的限制是否正好留下这个空白？

新颖性判断要引用具体文献和 locator；不要用“据我所知没人做过”。

### 6. 可行性评估

对每个假设评估：

- 需要的数据是否已有？没有的话能否公开获取或生成？
- 需要的实验平台、样本、伦理审批、时间、成本。
- 关键技术风险（抗体、敲低效率、测序深度、样本稀有性）。
- 如果只能做观察性研究，因果解释的强度够不够。
- 负结果是否仍然有信息量。

### 7. 排序

不要只按“我喜欢”排序。给出显式标准，例如：

- 证据支持度（现有证据）
- 可检验性/判别力
- 新颖性
- 可行性（时间/成本/风险）
- 影响（如果为真）

可以给权重和分数，但必须写理由。推荐 1–2 个“先做”的假设，并说明为什么不是其它。

## 四、假设质量检查表

一个可交付的假设应满足：

- [ ] 一句话能说清，不含“可能/或许/一定程度上”这类模糊词。
- [ ] 有明确的对象、条件、方向和可观测结局。
- [ ] 有机制，而不只是相关性。
- [ ] 有至少一个判别性预测。
- [ ] 有至少一个证伪条件。
- [ ] 与已知证据不冲突；冲突处有解释或标注。
- [ ] 不是同义反复（“因为 X 所以 X”）。
- [ ] 不是“需要更多数据”这种不可检验的表述。
- [ ] 可行性有具体路径，不是“做个实验就知道了”。

## 五、常见反模式

| 反模式 | 问题 | 修正 |
| --- | --- | --- |
| HARKing | 看完结果再编假设 | 先写预测，再看数据；在文档里保留时间戳/版本 |
| 稻草人竞争假设 | 竞争假设明显错误，显得主假设很强 | 写一个真正有竞争力的替代解释 |
| 不可证伪 | “调控网络很复杂，所以任何结果都支持” | 写出会杀掉假设的观察 |
| 相关性当机制 | “X 和 Y 相关，所以 X 调控 Y” | 加机制、加干预、加方向性检验 |
| 只追求新颖 | 忽略可行性/样本/伦理 | 同时给影响和可行性评分 |
| 假设太多 | 10 个假设，没有判别路径 | 收敛到 3–5 个，给出判别矩阵 |
| 忽略技术解释 | 把批次效应当生物学 | 先把测量/设计类解释列为竞争假设 |

## 六、与团队的分工

- 你把假设、预测、证伪条件、排序交给 PI。
- 需要实验设计/样本量/统计计划 → 交给 Researcher，附上判别矩阵和优先级。
- 需要文献边界 → 先用 `lit-review` 或让 Searcher 补检索。
- Reviewer 会用本 Skill 的检查表审查假设是否可证伪；交付前先自检。
